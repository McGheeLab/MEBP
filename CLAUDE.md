## ⚠️ Critical Safety Rules

**These invariants protect the hardware (a dragged/crashed needle bends the
needle, scratches the plate, or de-syncs the stage). Check them whenever you
touch stage motion, print execution, calibration navigation, or workflow travel.**

### 1. Retract Z to the "move" / safe Z before ANY cross-position XY move

Any time the stage moves XY **to a different location**, the needle MUST first
retract to the safe / "move" / travel Z **and the code must WAIT for Z to arrive
before the XY move starts**.

- **EXEMPT:** moving *within the same well* during a print/workflow (the print
  pattern itself — discrete `PRINT_PATH` segments, in-well trajectory waypoints).
  Z is intentionally at print height there.
- **EXEMPT:** manual incremental jog (arrow keys, jog buttons, Xbox, click-nudge,
  `move_xy_relative` / `move_xy_relative_um`) — user-controlled motion; the
  operator owns Z. Auto-retracting every nudge would make jogging unusable.
- **MUST retract:** click-to-travel, "Go To" well/A1/corner, return-home / `HOME_XY`,
  move-to-print-start (`MOVE_XY`), inter-well travel, plate-location scan hops.

**How to comply (use the existing primitives — do NOT bake a new ad-hoc gate):**
- Point-to-point travel → `StageController.safe_travel_to(...)` (raise → M400 +
  `wait_for_z_arrival` → XY → `wait_for_xy_arrival` → optional lower). It ABORTS
  the XY move if Z does not confirm at safe height.
- "Retract first, don't move XY yet" → `StageController.ensure_retracted_to(safe_z)`
  (raises to a height + waits; **never descends**).
- Print discrete travel → `PrintManager._retract_for_travel(...)` is invoked at the
  top of the `MOVE_XY` / `HOME_XY` handlers.
- Calibration navigation → `CalibrationPage._safe_navigate_to(...)`.
- Pick & place → `PickAndPlaceManager._safe_move_to` (inter-well = `safe_travel_to`;
  intra-well = small retract → wait → XY → lower).

**Never** write `if current_z >= safe_z: <move XY without retracting>`. That raw
comparison is **polarity-wrong** on ME3B V1 (`StageController.ZDIR = -1`, needle
descends as raw Z increases). Use the polarity-safe helpers
`StageController.z_height_of()` / `needle_at_or_above()`, or just always call
`safe_travel_to` (it is a near-no-op when the needle is already retracted).

A "retract for travel" must **never lower the needle** — only ever raise it in the
HEIGHT frame. A misconfigured/too-low travel-Z must degrade to a no-op, not a
crash-down. Never fall back to a raw literal travel height (e.g. `5.0`) — on
`ZDIR=-1` that is a *descent*; use `StageController.default_travel_z(ref, margin)`.

**Known gap:** `PrintTrajectoryPlanner` (pure-trajectory print path) still assumes
`ZDIR=+1` in its Z geometry, so its raise-before-travel is NOT safe on `ZDIR=-1`.
It logs a warning; prefer the discrete / hybrid-direct print path on ME3B V1 until
that planner gets a polarity pass. See
`coding plans/Update plans/MEBP_v75x_Z_RETRACT_BEFORE_XY_TRAVEL.md`.

### 2. Z polarity (ME3B V1)

The needle **descends as raw Marlin Z increases** (`ZDIR = -1`). Never assume
"up = larger Z". Do height comparisons in the `ZDIR`-scaled height frame.

## Project Overview

MEBP is a Python/PySide6 desktop application for controlling laboratory bioprinting equipment. It orchestrates Prior ProScan XY stages, Marlin Z/pump controllers, and Hamilton syringe systems for multi-material biological printing.

### Key Directories

| Path | Purpose |
|------|---------|
| `main.py` | Entry point — CLI args, mode selection |
| `SupportClasses/` | Backend modules — zero GUI dependencies |
| `gui/` | PySide6 frontend — pages, widgets, dialogs, styles |
| `config/` | Hardware configs, controller protocols, print files |
| `coding plans/` | Architecture docs, update plans, readmes |
| `tests/` | Test suite |
| `patches/` | Legacy version upgrade patches (deprecated — content migrated to update plans) |

### Core Design Principles

1. **Hardware abstraction** — GUI pages never touch serial ports. All hardware access through `StageController` or `PrintManager`.
2. **JSON protocol abstraction** — XY commands defined in `config/controllers/` JSON files.
3. **Hardware-first** — Page 0 (Hardware Setup) must complete before other pages unlock.
4. **µL-native pumps** — All user-facing pump values in microliters. Conversion to mm happens only inside `StageController.move_pump_uL()`.
5. **Safety-layered** — Software endstops, flow-rate clamping, crash recovery throughout.
6. **DPI-aware GUI** — All pixel dimensions go through `gui/scaling.py` so the UI scales correctly on any screen (1080p → 4K/Retina). QSS theme generated by `build_theme(scale)`.

## Update Plans

For each update task in a version, a plan document **must** exist in:

`coding plans/Update plans/`

### Naming Convention

`MEBP_v{from}_to_v{to}_UPDATE.md` — e.g., `MEBP_v728_to_v729_UPDATE.md`

### Plan Document Requirements

Each update plan is a **living document** that must include:

1. **Objective** — What this update accomplishes
2. **Files Modified** — List of all files touched with brief rationale
3. **Implementation Steps** — Ordered checklist of changes
4. **Status Tracking** — Mark each step as: `[ ]` pending, `[x]` done, `[~]` in-progress
5. **Testing Notes** — How to verify the changes work
6. **Issues & Decisions** — Log of problems encountered and decisions made during implementation

### Workflow

- Before starting work on a new update task, **create or update** the plan file
- As work progresses, **update the status** of each step in the plan
- When complete, ensure all steps are marked `[x]` and add a summary of what was done

## Code Conventions

- **Theme**: Catppuccin Mocha dark (QSS generated by `gui/styles.py::build_theme(scale)`)
- **GUI Scaling**: All pixel dimensions through `gui/scaling.py::s()`, font sizes through `scaled_font_size()`. Never hardcode raw pixel values in GUI code.
- **Config format**: JSON everywhere (hardware, controllers, prints, settings)
- **Trajectories**: Nx7 numpy arrays `[x, y, z, p1, p2, p3, t]`
- **Serial**: pyserial RS-232, retry decorator with exponential backoff
- **Threading**: `Processor` command bus for thread safety; Qt signals for GUI updates
- **Testing**: unittest + physics-based simulators (`XYStageSimulator`, `ZPStageSimulator`, `SimulatedCamera`)
- **Vision**: OpenCV-based detection in `VisionDetector.py`; `DetectionWorker` QThread for parallel processing; `DetectionOverlay` for camera feed annotations
- **Executable**: PyInstaller via `python build_exe.py` — produces `dist/MEBP/` standalone folder
